Why AXIOM

From an SLM to a Financial Decision Engine

AXIOM is not an LLM wrapper.

It is an open-source reasoning model trained from a Qwen2.5-1.5B foundation using supervised fine-tuning (SFT / QLoRA) and reinforcement learning (GRPO), with process-level verification and adaptive reasoning built into the stack.

We are now adapting this reasoning stack toward financial decisions — where the model must reason about context, evaluate alternatives, verify its decision, and only then recommend or execute an action.

The financial specialization is in progress. It is being trained and adapted; it is not a completed capability.

Technical approach

The stack, end to end

Each stage is implemented in the AXIOM repository unless marked otherwise. We separate what is built from what is being adapted and what is planned.

Open-weight foundation model. Apache 2.0.

Open-source fine-tuningBuilt
Reasoning traces distilled and compressed under a token budget with an answer-preservation check.
03
SFT / QLoRABuilt
4-bit NF4 QLoRA, LoRA r=16 / α=32 on all linear layers, curriculum ordering.
04
GRPO reinforcement learningBuilt
Composite reward: correctness + verifier score − length − repetition. Verifier frozen, KL-leashed to the SFT reference.
05
AXIOM small reasoning modelBuilt
A trained SLM that reasons in explicit, segmented steps.
06
Adaptive reasoning depthBuilt
Confidence-driven continue / expand / exit controller under hard depth and token caps.
07
XD-PRM process verificationBuilt
Five scalar heads scored per reasoning step: logic, commonsense, consistency, efficiency, confidence.
08
Financial adaptationIn progress
Training and adapting the model and its verifier toward payment context, recovery strategy and financial risk.
09
Verified financial decisionPlanned
Pass / revise / escalate gate on a financial action, with calibrated confidence.

Revenue recovery actionPlanned
Execution against Razorpay. No integration exists today.

Why this matters

Why Verification Before Action?

Reason

Financial actions require contextual reasoning — the failure code, the customer's history, the merchant's policy and the timing all change the right answer.

Verify

The model's reasoning is checked before consequential actions. A verifier that scores each step independently can refuse one the reasoner was willing to take.

Escalate

Uncertain or high-risk cases can be routed to stronger models or human review, rather than being resolved by a confident guess.

AXIOM's process verifier (XD-PRM) and adaptive-depth controller are implemented in the repository. Their adaptation to financial dimensions, and the escalation policy above, are in progress and not yet production implemented.

Architecture

Local-First by Design

AXIOM is being designed toward local-first financial intelligence — keeping merchant business context under merchant control wherever practical, and escalating only when additional model capability is required. A 1.5B-parameter foundation is what makes local execution realistic at all.

This is a design goal, not a guarantee. We make no claim of absolute privacy, zero cloud use, guaranteed data locality, or compliance certification.
